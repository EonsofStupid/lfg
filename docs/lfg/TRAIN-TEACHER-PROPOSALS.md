# Train-only local teacher proposals

`ml/lfg-encoder/train_teacher_proposals.py` accepts a digest-pinned masked export only when its manifest lists `train.jsonl` as the sole split. It reads the manifest, export config and literal train file once, verifies their configured and manifest digests, then makes an exclusive owner-private snapshot of those exact bytes for `masked_supervision.load_export(train_only=True)`. It rechecks the source manifest/config/train bytes before transfer and publication. A manifest that lists validation or any other split is rejected before config/train access; a later manifest replacement cannot change the loader's pinned snapshot. Configuration may select row-ID digests and a bounded row count; source text is not stored in configuration.

Local snapshot and worker-config temporary directories use the masked-supervision owner-only permission helper. Newly created files have that same policy established and verified before any payload bytes are written. On Windows, this removes inherited and explicit access outside the current owner/logon principals; it does not grant SYSTEM or Administrators access. POSIX paths are checked as mode `0700` directories and `0600` files. Report publication directories retain the comparator's strict owner, SYSTEM and Administrators allowlist. The task resets ACLs on its exclusively created report directory before installing those grants, then verifies the owner SID and exact explicit principal set; an inherited or explicit LogonSessionId ACE is not added to the comparator allowlist.

The adapter requires a private `lfg.train-teacher-proposals-config.v1` JSON file. It pins the export manifest/config/train, taxonomy, screening policy and screening code digests, selected columns, row selection, byte bounds and private output location. It refers to the existing private local-comparison configuration and reuses its acquisition receipt, model artifact verification, runtime identity, resource rules and SSH host checks. Each actual run first completes a separate task-owned zero-row transient worker lifecycle: a unique owner-private remote directory, hash-verified adapter/comparator/config files, task-local model store, systemd resource scope, network namespace, same-user loopback service, worker readiness identity, and a host-namespace listener denial probe. The worker receives only an empty payload, performs its warmup, stops the service and verifies cleanup. The actual lifecycle requires the probe's host, model, runtime, config and code identities to match before it sends selected train rows. No long-running shared worker is used.

Python starts the staged worker with isolated mode. A small bootstrap verifies the exact config, adapter and sibling comparator digests before adding that staged directory to the import path, then starts the worker entry point. This keeps isolated startup compatible with the comparator dependency without admitting an unverified import path.

The worker now uses two control stages. It first reports the isolated runtime boundary without accepting payload; the controller verifies the host namespace cannot reach the loopback listener and returns a nonce-bound empty warmup acknowledgement. Only then does the worker warm up, verify the loaded model and artifact layer bytes, and issue a separate ready-for-data event. The controller checks those identities against the zero-row probe before sending any selected train rows. A denial or identity mismatch stops before data transfer.

```sh
python ml/lfg-encoder/train_teacher_proposals.py --config PRIVATE_CONFIG.json --zero-row-probe
```

The explicit `--zero-row-probe` command performs only that empty-input lifecycle and does not open export files or create a proposal report. The normal command repeats the probe automatically before opening any training payload to the worker. Before the first actual run, independently review the implementation and accept the standalone probe evidence.

Proposal results are published atomically to a new owner-private directory outside every Git worktree, with an incomplete marker retained if publication fails. A verified terminal checkpoint is checked against the durable row events for every status, count, claim, abort reason, uncertainty field, source identity, model/config identity, payload hash and event digest before publication. Rechecking a complete destination compares the entire persisted manifest, including its original timestamp and original zero-row probe observations, byte-for-byte with that terminal report. A fresh recovery probe is recorded in a separate private checkpoint receipt; recovery compares its stable host, model, config, code and server identities while retaining the original probe and teacher worker PID and network namespace observations as historical evidence. A capacity-only increase preserves the original raw config digest, records each new config digest in the monotone capacity history, and leaves the normalized task/config binding unchanged; source, model or inference-policy changes fail before mutating checkpoint state. A report without a verified terminal checkpoint is derived as `partial_aborted_ambiguous`, remains unverified, and omits per-resume time, probe and resource snapshots so identical durable row evidence has a stable result. Before revising any parent report, the adapter validates its full manifest and source-ordered proposals against the exact historical event-log prefix and either the matching terminal record or an immutable publication receipt for an explicitly unverified partial. If retrying a published partial, the adapter reserves an owner-private sibling destination and records its parent manifest and proposal digests before sending rows. The new report links to that parent and never replaces it; reservation or destination ambiguity fails before inference. An interrupted empty reservation directory can recover its missing marker only when its exact path is bound by the durable revision record and its ACL verifies; foreign entries or a changed marker fail closed and remain preserved. Recovery accepts only publication-ID-bound marker, proposal and manifest staging files whose bytes validate as an expected prefix or full report. It retains validated interrupted staging files, republishes from durable proposal rows without consuming earlier evidence, and refuses altered, foreign, unknown or excessive staging entries without mutation. If evidence is ambiguous or does not validate, stop and preserve the output and checkpoint for review; do not delete staging files to force resume. Windows ACL and process-death guarantees are subject to the platform limits described below. The manifest binds export lineage, adapter/comparator/config/model hashes and receipt, host boundary, resource snapshots, row counts, per-label coverage, worker statuses and omission policy. JSONL stores row/source and screened/original-text digests, source target/mask/origin/reviewer claims, and proposal states; it excludes request bytes, raw responses, screened text and exception content. Teacher outputs are unreviewed claims and promotion-ineligible. By default omitted labels stay unknown; `assume_exhaustive_labels` is an explicit operator setting that records omitted labels as unreviewed negative proposals. Conflicts remain in both source claims and proposal results. A transport or worker failure with ambiguous inference lifecycle aborts all later rows as not attempted.

Before the controller sends selected rows, it creates an owner-private checkpoint directory beside the configured output, named `.<output-name>.teacher-progress`. It is outside Git and must not already exist for a fresh run. A stable sibling lock file holds an OS-level exclusive lease for the whole run; a fresh file is exclusively created, secured before writing its sentinel byte, and verified as a regular single-link file. Windows uses a nonblocking byte-range lock and POSIX uses `flock`; an unsuccessful contender does not unlock another process's lease. The kernel releases the lease on process exit, and the lock file is retained to avoid inode replacement races. `checkpoint.json` binds the exact export/config/taxonomy/selection order, selected source identity digests, comparison and request/resource config, prompt contract, model/server identity, runtime boundary and adapter/comparator code hashes. The worker streams each bounded row event before starting the next row inference. `events.jsonl` contains only source-bound, validated proposal events; each event is appended and `fsync`ed before the controller sends an ACK bound to the attempt, row index and event digest. The worker will not start the next row until it receives that ACK. Per-attempt records say that listed rows were prepared for sending and that their request outcome may be unknown. A crash after a request was sent but before its event was durably recorded leaves the outcome unknown; explicit resume can repeat that inference, so processing is at-least-once and is not exactly-once.

After a verified worker result, cleanup and source recheck, a terminal checkpoint records the event-log digest and report manifest before final publication starts. If the process stops after renaming the private output directory but before replacing its incomplete marker, `--resume` recognizes only the matching publication ID and exact proposal bytes, then atomically completes that manifest replacement. It will not overwrite unrelated output. Ambiguous statuses (`timeout`, transport/protocol errors, identity mismatch, incomplete response, request-too-large and not-attempted-after-abort) remain eligible for retry on explicit resume. A new attempt supersedes the latest row result while the old event and attempt record remain in the private log. Duplicate indices within an attempt, duplicate JSON keys, truncated lines, corruption, changed bindings and unsafe storage fail closed without deleting checkpoint evidence. If an interrupted attempt left all rows individually validated but did not leave a verified terminal result, resume can publish those claims only as `partial_aborted_ambiguous`, with `terminal_worker_result_verified: false`; it does not promote them to a complete report.

On POSIX, each checkpoint file is flushed with `fsync`, and the checkpoint directory and its parent are synced after entries are created. On Windows, checkpoint files are owner-private and opened without following links where the platform exposes that flag; each event is flushed with Python's `fsync`/CRT commit before the next event is read. Process-death recovery is tested separately from Python exception cleanup. Python does not provide a portable directory flush operation here, so power-loss durability of Windows directory metadata and storage hardware is not guaranteed; unsupported filesystem locking or privacy verification fails closed. The log has a separate `max_progress_store_bytes` ceiling, initially selected from the bounded protocol/output estimate and capped at 1 GiB. It can be increased for an explicit resume; a monotone, integrity-checked capacity history prevents silent decreases, and rejected identity/evidence mismatches do not mutate that history. Preflight includes the serialized checkpoint envelope, event digest and JSON framing under the per-record limit. A whole attempted batch is capacity-checked before sending. The controller protocol queue holds at most four 1 MiB lines, and records are capped at 1 MiB with an identity header capped at 16 MiB. Checkpoint state does not turn teacher proposals into verified labels.

This adapter does not access validation, test or heldout rows and does not train a model. A successful probe or proposal run does not establish label accuracy, verified screening, model quality or promotion eligibility.

On a failed controller or worker invocation, stderr includes one `lfg.teacher-lifecycle-diagnostic.v1` JSON record. It contains only a fixed controller phase, a generic failure category, and an independent cleanup status. Directory and local config setup are distinguished as `remote_task_directory`, `local_temp_directory`, and `local_config_file`; source recheck and publication have distinct `source_recheck` and `publication` phases. Later transfer and verification keep their existing phases. The legacy `task_directory` phase remains accepted for older reports. When the worker reports a failure through its bounded protocol, the record also contains the fixed worker phase, category and cleanup status. Exception text, paths, command arguments, prompts, responses and stderr are never copied into it. A phase is the last confirmed stage, not a root-cause diagnosis. `unknown` is used when the stage is not confirmed. The existing generic failure message and exit behavior remain in place. Historical failures cannot be classified from this record retroactively.

## Explicit tri-state response mode

The optional `teacher_response_mode: "lfg.teacher-explicit-labels.v1"` selects the versioned explicit-label contract described in [TEACHER-EXPLICIT-LABELS.md](TEACHER-EXPLICIT-LABELS.md). Omission retains legacy positive-list mode. The opt-in mode requires `assume_exhaustive_labels: false` and an operator-supplied `teacher_prompt_contract` no larger than 16 KiB with both `{identities}` and `{text}` slots. The controller sends a generated schema for the exact ordered taxonomy and digest, accepts only complete model-bound replies, persists positive/negative/unknown as separate unreviewed claims, and treats every omitted identity as unknown. This does not assert that a deployed server or model honors structured output; malformed responses remain unasserted. Exact prompt, schema, parser module, taxonomy, source, model and worker identities are bound through zero-row readiness, durable row ACK/checkpoint, publication and resume. Accepted parser extension values are retained as inert data in an owner-private record bound to the same row, attempt, event and model/schema identities; extension bytes are bounded by `max_teacher_extension_bytes` and fsynced with the progress event before ACK. Missing and present-empty extensions are distinct. Public events, diagnostics and reports omit their values; an explicit `read_private_teacher_extensions` call is required to retrieve them. They do not affect labels, weights or trust. Windows process-death recovery is tested, while power-loss durability of directory metadata and storage hardware is not guaranteed. The claims remain unreviewed and promotion-ineligible. No private data collection, training bridge or model-quality qualification is part of this integration.

Checkpoint SHA-256 values detect accidental corruption and task-identity drift; they are not cryptographic authentication against an actor able to rewrite the owner-private store and its hashes. Owner-only filesystem controls are part of the local trust boundary.
