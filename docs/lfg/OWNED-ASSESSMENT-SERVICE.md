# Experimental owned assessment service

The owned assessment API is an opt-in local inference route backed by the experimental owned byte ONNX checkpoint. It does not alter the deterministic `POST /api/lfg/assess` endpoint and never substitutes deterministic output when the owned runtime is unavailable.

## Local setup

Build the server with `--features owned-byte-onnx`. Copy `crates/lfg-server/config/owned-assessment-service.example.json` to an owner-only location outside the repository, then set `LFG_OWNED_ASSESSMENT_CONFIG` to that file. Set `LFG_OWNED_ASSESSMENT_TOKEN` to a randomly generated secret with at least 32 non-whitespace bytes and at least 12 distinct byte values. The token is separate from `LFG_FEEDBACK_TOKEN`; using the same secret is an operator choice. Do not put either token in a URL, source file, or log.

Both routes require `X-LFG-Session-Token`, a loopback listener and loopback peer, a Host matching the bound listener (or `LFG_OWNED_ASSESSMENT_ALLOWED_HOSTS`), and an absent Origin or an allowed matching local Origin. Configure `LFG_OWNED_ASSESSMENT_ALLOWED_ORIGINS` only for specific local UI origins. A missing or invalid token never has a bootstrap path. The API is not an authenticated hosted service.

The JSON config uses schema `lfg.owned-assessment-service.v1`. The example sets `enabled` to false; set it explicitly to true to enable the service. Artifact, framing, training-manifest, and native runtime paths are operator supplied; status responses never disclose them. Pin `expectedModelSha256` and `expectedFramingSha256` to the verified private artifacts. `maxMetadataBytes` bounds framing and training-manifest files. `maxRuntimeConfigBytes` bounds native runtime configuration bytes and is passed to the child with a SHA-256 pin, which it verifies against the bytes it actually reads before parsing. Only the small service config itself has a fixed 128 KiB bootstrap read cap. `maxHttpBodyBytes` bounds the complete JSON request body, including JSON escaping and extension fields. `maxRequestBytes` separately bounds the UTF-8 bytes in `text`. Unknown request fields are accepted and ignored.

`maxContextBytes` must fit both the native runtime context and model manifest context. It measures the full framed prompt in UTF-8 bytes. `maxGeneratedBytes` must fit the runtime's configured generation limit. `maxWorkerOutputBytes` bounds the serialized worker response and must have room for the configured generated byte array, worst-case JSON escaped text, and JSON framing. `timeoutMs`, `maxConcurrent`, and `workerThreads` are operator settings. Positive values and runtime relationships are checked; the worker output stream stops at its configured cap, and a timed-out child process is killed and reaped before the request returns.

`workerThreads` is passed to the child through `RAYON_NUM_THREADS`, `OMP_NUM_THREADS`, and `OPENBLAS_NUM_THREADS` before runtime startup. These are cooperative library settings. The backend does not verify that every tract/ONNX operation honors them and does not enforce CPU-cycle quotas. `maxConcurrent` bounds simultaneous inference child processes, not CPU cycles or work by other processes. Use OS-level resource controls when hard CPU quotas are required.

The service checks the ONNX model hash against its manifest, checks the configured model hash, pins and hashes the complete framing file, verifies the system string against its recorded system hash, and links the source weights and training manifest hashes recorded in the ONNX manifest. It also checks the framing's training/config hash fields against the training manifest. For current SFT manifests, `framing_sha256` additionally binds the six delimiter values actually used by SFT to the values served at inference. The pinned framing-file hash remains an operator-controlled identity check; legacy manifests without `framing_sha256` lack the training-to-delimiter link.

Training manifests from the current owned SFT trainer carry `system_sha256` and `framing_sha256`. The service checks the system bytes and recomputes the canonical framing digest from the six actual delimiter strings in the serving framing file. A delimiter change with an unchanged training claim is rejected. Older manifests without these fields remain loadable for compatibility, but are explicitly unlinked from those training inputs.

## API

`GET /api/lfg/assess/owned/status` requires the same token as inference. It returns `status: "disabled" | "unavailable" | "ready"`, `enabled`, `engine` (or `null`), configured bounds in `limits`, and a machine-readable `reason` when not ready. It does not return file paths or secrets.

`POST /api/lfg/assess/owned` accepts `{ "text": "...", ...extensionFields }`. Optional `context` and `contextSha256` fields add digest-checked project context with the same byte rendering as teacher collection: context text, two newline bytes, then request text. Context is opaque transport; the API does not validate its source, freshness, model availability, or subscription status. When a context digest is verified, the response includes `projectContextSha256` (the digest only, never the context text) so a caller can explicitly attach the identity to a feedback record. The assessment route does not create or automatically join feedback records; callers must preserve this metadata explicitly. With neither field, legacy request framing is unchanged. Inference responses use HTTP 200 and always include numeric `elapsedMs`, `status`, and `engine` (possibly `null`). Result statuses are:

- `ok`: the worker stopped at the configured assistant suffix and returned a JSON object that satisfies the configured output policy; this does not verify its correctness.
- `truncated`: byte/context generation limit ended output; bounded partial `outputText` is returned even when it is not complete JSON.
- `context_limit`: the fully composed prompt exceeded `maxContextBytes` before starting a worker.
- `invalid_input`: request JSON or text is invalid, empty, or over its configured byte limit.
- `busy`: all configured inference slots are occupied; no worker was queued.
- `timeout`: elapsed-time limit was reached; the worker process is killed and reaped.
- `malformed_output`: worker output is invalid, or a stop-complete response is not a JSON object. Bounded `outputText` is retained for explicit user review.
- `incomplete_output`: a stop-complete JSON object is missing one or more operator-configured required fields. The partial object and bounded `outputText` are returned for explicit review; it is not treated as a complete assessment.
- `inference_error` or `unavailable`: worker/runtime failed or could not start.

`requiredOutputFields` is an operator-defined list of `{ "name", "valueType", "nonEmpty?", "minInteger?", "maxInteger?" }` constraints. The example policy uses `intent` (non-empty string), `complexity` (non-empty string), `suggested_models` (array, including an empty array for no recommendation), `agent_count` (integer at least 0), and `reasons` (non-empty array). Operators must configure the policy to match their checkpoint and may use a different contract. The UI displays `reason` and `reasons` as separate fields when present; it does not silently rename either. Extra fields are retained. Missing required fields produce `incomplete_output` and return the parsed partial object for review. A wrong type or failed value constraint produces `malformed_output` with bounded raw text. A stop-complete object satisfying the configured contract is the only path to `ok`. Model-generated content remains untrusted and is never treated as a verified assessment fact. Prompts and output are not logged or persisted by the server. The UI may keep inference in memory until the owner explicitly chooses to save feedback.

The status identity includes model, model-manifest, source training-manifest, framing, runtime config, and validated service config SHA-256 values. These digests let saved feedback distinguish output policy and runtime versions without storing paths or configuration content. The experimental byte checkpoint is not qualified for assessment accuracy or representative CPU performance; successful inference only demonstrates this configured execution path.

## Local observation, 2026-11-03

An owner-authorized, completed Spark assessment checkpoint was copied to a private local directory with its weights digest verified, then exported to ONNX. PyTorch and ONNX Runtime agreed at the four configured short prefix lengths; the largest absolute difference was approximately 0.0000172. A native Rust CLI run on one actual owner request, with two worker threads requested and a 512-byte generation limit, took 423.594 seconds including process startup on an Intel Core Ultra 9 275HX. It reached the byte limit and its output was invalid JSON. That single trial does not establish task accuracy or representative latency, and the requested thread count is not a measured CPU quota. The private artifact and detailed observation remain outside Git.

A release-mode API smoke test using the same private checkpoint and an actual owner request returned `truncated` after 8 generated bytes in 3.926 seconds with two worker threads requested; the short limit was intentional for the smoke test. The authenticated endpoint, origin rejection, input limit, and existing deterministic endpoint were also exercised. This verifies the execution path, not assessment quality.

The 470 authorized private teacher-training responses used for the completed Spark assessment checkpoint were checked in aggregate: all 470 contained a `reasons` array, not a `reason` string. The earlier example policy requiring `reason` could therefore reject output matching the actual training contract; the example is corrected here. This is a schema check, not proof that the teacher proposals are correct. Of those responses, 455 exceeded 512 UTF-8 bytes, so a 512-byte generation limit frequently cannot fit the training response length. Limits must be chosen from the configured artifact and measured workload; increasing the limit alone did not repair this checkpoint?s invalid output.

The same 470 training proposals all contain an empty `suggested_models` array, and 60 contain an `agent_count` of zero. An empty array or zero is an absence of a usable recommendation, not an actual subscription-aware plan; these values are preserved for review. All 470 examples claim unreviewed status and unknown outcome. The example output policy now permits those representations, while users can configure stricter policy for their own checkpoint.
