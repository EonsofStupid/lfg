# Per-node validation against the deterministic kernel

`ml/lfg-encoder/node_evaluate.py` reruns an operator-selected LFG binary with
the exact snapshot on approved **validation** examples from the
[per-node review workflow](NODE-REVIEW-AND-ADMISSION.md). It reruns the
admission audit from the source queues and ledgers; it does not trust a separate
training export's claim of eligibility. The runner refuses to evaluate when
admission fails. It does not train a model, run the test split as an evaluation,
or qualify a binary.

```powershell
python ml/lfg-encoder/node_evaluate.py `
  --input PRIVATE_QUEUE.jsonl PRIVATE_LEDGER.json `
  --snapshot SNAPSHOT.json --policy PRIVATE_POLICY.json --node NODE_ID `
  --kernel-binary target/release/lfg-server.exe `
  --timeout-seconds 30 --max-validation-items 1000 --max-input-bytes 10485760
```

Use repeated `--input QUEUE LEDGER` pairs for all relevant sources. The numeric
limits are examples; choose appropriate bounds for the environment. The runner
passes validation text to the selected local process on stdin and holds its
output in memory. It checks the binary, input, snapshot, policy, and optional
operations configuration hashes before and after the run, validates the
returned IDs and input and snapshot digests, and prints aggregate metrics
without request text. The selected binary and local filesystem must be trusted;
these checks do not authenticate the binary or prevent concurrent tampering.
The current audit reads the supplied test records for support and separation,
so this workflow is not a blinded holdout. Preserve a genuinely independent,
access-controlled test for final evaluation.

For each reviewed validation item, the baseline is counted as **correct** or
**wrong** when it commits a choice at the target node, **escalated** when it
stops at that node without committing, or **not reached** when it stops or takes
a different path earlier. A choice hop can contain the provisional top-ranked
option even when threshold or ambiguity checks subsequently escalate at that
same node; that is an escalation, not a committed choice. The report includes
per-reviewed-choice counts and:

- `selectionRate = (correct + wrong) / total`.
- `accuracyAmongSelected = correct / (correct + wrong)`.
- `correctPerReviewedItem = correct / total`.

Rates with a zero denominator are null. These are conditional node metrics,
not end-to-end task success, calibrated confidence, latency, or proof of
quality. Queue construction only includes nodes reached or escalated to under
the recorded snapshot; this selection can bias the sample. Assess the sampling
plan and obtain representative reviewed data before interpreting metrics.

For exploratory comparison, `--candidate PRIVATE_PREDICTIONS.jsonl` accepts
one `lfg.node-prediction.v1` record for every validation item with fields
`itemSha256`, `inputSha256`, `snapshotSha256`, and `choice` (a valid option or
null for abstention). Item IDs are available from the review ledger or from
the admitted train/validation handoff. The runner requires exact coverage and
matching digests. It scores this proposed fallback **only on items where the
kernel escalated at the target node**, reporting eligible, correct, wrong and
abstained counts plus selection rate, accuracy among fallback selections, and
`(baseline correct + fallback correct) / total`. It does not substitute a
prediction when the kernel already selected or did not reach the node.

These are supplied predictions: the runner does not execute a candidate model
or verify that the file was generated by any particular weights. The report
explicitly states `candidateExecutionVerified: false` and
`qualificationEstablished: false`. A reproducible trainer, independently
verified candidate inference, confidence and performance measurements, and
held-out evaluation remain required before promotion.

An [experimental per-node exemplar builder](NODE-EXEMPLAR-EXTENSION.md) can
produce candidate prediction files after the review and admission gate passes.
It remains an offline Python path and has not been qualified for release.

## Local evidence

On 2026-10-31 the runner was invoked against the real local LFG queue. It
refused to evaluate because there were zero approved labels and did not produce
quality metrics. The existing 11-item queue was checked against its journal:
none of its `baselineChoice` fields was affected by the provisional-hop issue.
The evaluation and corrected journal queue were tested against actual local
kernel binaries on Windows and Spark using test-only fixtures; these tests are
not training or quality evidence. No private requests were sent to the Spark.
